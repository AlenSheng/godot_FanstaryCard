## 1. 权威

PVE 与 1v1 **同一套服务端结算**。客户端只发意图，不提交伤害、抽牌、掉落、骰点、金币结果。

切片：强制标准难度、临时牌池空、不掷红。红装周配额字段可占位，原型永不置 1。

防具 +4/+5 各消耗 1 件同品质仓库装备；绑定材料允许，部位/元素/强化等级不限。红装必须消耗红装，不接受橙装替代。该入口随红装掉落与周配额开放；当前原型没有红装正常来源。

大厅经济过服：商店日限、市场 8 栏 / 48h / 10% 抽成、魂与碎片分账、专属武器不可上架 / 不进堆。不以客户端报拥有为准。

## 1.1 通信编码

- 第一方登录及内部玩法 REST 使用 `application/protobuf` 与类型化错误；外围公告、管理和登录前信息保留 UTF-8 JSON。旧游戏 JSON 仅通过显式兼容开关提供。迁移范围与验收见 [网络迁移计划](network-protobuf-migration/PLAN.md)，保持既有 HTTP 状态码、鉴权、事务及幂等语义。
- `/ws/v1/session` 只接受/发送 Protobuf 二进制帧，schema 为 `protocol/realtime/v1/realtime.proto`；文本帧以 `InvalidMessageType` 关闭。
- Protobuf 信封必须带 `protocol_version=1`，每条完整消息上限 16 KiB。`payload` 只能装对应的具名 Protobuf message，禁止内嵌 JSON。
- 字段号发布后不可复用；兼容新增字段，删除字段须保留编号；破坏性变更新建协议版本。
- 实时协议时间为 Unix 毫秒；`requestId / sequence / roomRevision` 语义不变。
## 2. 房间与 tick

一局一场房间。房间时钟 **10 Hz**。「同帧进格」= 同一 tick 内的进入请求，先手随机。

权威计时全部用房间时钟，不信客户端：

| 计时 | 值 |
| --- | --- |
| 后手锁 | 0.8s |
| 双方离开窗口 | 8s |
| 强制逃脱读条 / 失败 CD | 2.0s / 12s |
| 停战缓存 | 45s 或曼哈顿 ≥ 3 |
| 撤离读条 | 约 3s |
| 泉水读条 | 1.2s |
| 药剂 | 无计时；行动栏点击立即消耗与恢复 |
| 断线宽限 | 15s |
| 匹配不满也开 | 30s |

```text
EnterCell
  → 有可配对空闲者：快照 PVE，重置抽 3，进入 PVP
  → 无人可配：开始或继续 PVE
PVE 清怪 → 三选一 → 行动栏
PVP 存活结束 → 恢复快照 → 怪未清则回 PVE，已清则回行动栏
PVP/PVE 生命 ≤ 0 → 死亡结算
行动栏走邻格 → EnterCell
```

进格豁免按 GDD 5.5 **原样实现**（含 Boss 格 C 与胜者互不打）。行为翻案须二次确认，服务端不得自行「修掉」。

## 3. 数据结构（逻辑，不必先定 ORM）

**房间**

- 36 格钉死：怪组、泉水、撤离、匣灵、Boss
- 停战缓存对、进格豁免对
- `configVersion`、`seed`、难度=标准

**每玩家**

- 探索包 / 安全格、穿戴五部位 + 专属武器
- 本局池与三堆（手牌上限 5）
- 独立 PVE 实例：怪生命 / 护盾 / 意图 / 计时
- 冻结快照槽（空或一份）
- 三选一刷新次数（每玩家每局 3）
- 抽牌蓄能、焚弦 C、抽牌加速剩余、眩晕窗口

**格**

- 共享遗物堆列表（按死者名分堆）
- 可并行：多场 1v1 + 多人独立 PVE

## 4. 冻结快照

写入时机：切 1v1（含行动栏 / 三选一 / 遗物 / 撤离读条被拉打）。

| 字段 | 快照 | 1v1 工作副本 |
| --- | --- | --- |
| 生命 / 护盾 | 拷贝 | 从快照拷贝入手（同格不清盾） |
| 手牌 / 库 / 弃牌 / 玩家抽牌 RNG 状态 | 拷贝 | 本局池新洗，抽 3 |
| 蓄能 | 拷贝 | 从 0 再充 |
| 焚弦 C | 拷贝 | 0 |
| PVE 抽牌加速剩余 | 拷贝 | 1v1 不用这条 |
| 对该怪的眩晕窗口 | 拷贝 | 1v1 对玩家另计 |

冻结快照还必须深拷贝该玩家的独立 PVE 实例，至少包括每只怪物的生命、护盾、意图索引、间隔进度、前摇剩余、蓄力、强化、眩晕和其他状态计时。进入 1v1 后该实例完全暂停，不得只保留对象引用；非死亡结束时与玩家快照一起原样恢复。

存活结束（胜 / 双方离开 / 逃脱）：丢 1v1 副本，恢复快照。  
1v1 死亡：走 GDD 2.5.2，不恢复。

蓄能只在 PVE / 1v1 战斗 tick 中增加。行动栏、走动、三选一、遗物、读条暂停（不清零）。

## 5. 匹配

- 创建 preparation 时，实际穿戴防具从 `Equipped` 原子切到 `PreparationLocked`；主动取消、排队取消、准备过期或 Ready 超时剔除时恢复 `Equipped`。正式开房时转为 `InMatchEquipped`，并在同一事务扣除带入药剂；付费探索包保持逻辑预留，只在死亡结算时消耗，撤离直接释放。失败整笔回滚。
- 队列只收 1–4 名已准备真人。满 **4 名真人** 立刻开，不补机器人。
- 未满 4：等到 **30 秒**（队内第一人入队起算），用补位机器人补到 4 再开。取消「1 人立即开房」。
- 原型只进标准难度，无选档。
- 机器人生成、练度、局内决策见 GDD **5.14** 与 `FantasyCard.Domain.Bots`。客户端 **不下发** `isBot`。

## 5.1 补位机器人（房间）

RoomActor 每 tick 调 `BotDirector.Decide`，只执行返回的意图：

- **PVE**：不跑出牌流水。到层计时后扣 `PveHpLossPercent`，至少留 1，再走三选一。
- **对真人 1v1**：同一套权威结算 + `SelectDuelCards` 中等出牌。不主动离开 / 逃脱。
- **机机**：10 秒后按生命百分比定胜负并扣 15% / 35% L。
- 无真人剩余：`ShouldEndRoom` → 立刻结束，机器人带出销毁。
- 小地图投影标 Boss 与泉水、自己的位置，并提供当前未撤离/未阵亡玩家总数；不提供其他玩家位置或交战状态。

## 6. 掉线 / 重连

- 断线保留房间席位 **15 秒**，可 `session.resume` 回原状态。
- 15 秒超时按 **死亡** 结算（GDD 2.5.2 / 5.10）。不发明掉线无敌挂机。
- 1v1 中一方断线：15 秒内 **双方不能出牌**（等待）。超时：断开方死亡，在线方按 PVP 胜处理并恢复己方快照（若其 PVE 未清）。
- 结算事件必须落库；只有资产 hold 全部离开 Pending 后，重登 bootstrap 才返回尚未确认的结算，不重复发奖。客户端展示成功后通过玩家归属校验的确认接口标记已查看，重复确认返回首次确认时间。

15 秒内服务端 PVE 意图是否继续：PVE 单人断线时房间时钟继续（怪仍出手）；1v1 双方停手。与「短暂断线不自动判死」不冲突——判死只在满 15 秒。

## 7. WebSocket 指令（房间）

客户端只发意图。成功走事件 + ack；失败 `error.command_rejected`。

| type | 何时合法 |
| --- | --- |
| `map.move` | 行动栏，四邻且不向外 |
| `battle.play_cards` | PVE / PVP，手牌合法，后手锁已解除 |
| `battle.select_target` | PVE 多目标 |
| `choice.refresh` | 三选一，次数 < 3，金够 |
| `choice.pick` | 三选一；包满须带替换格 |
| `relic.take` / `relic.replace` | 行动栏检索 |
| `action.spring` | 行动栏，非战斗；权威读条 1.2s |
| `action.potion` | 行动栏且背包有药剂；立即消耗 1 瓶并恢复，无读条 |
| `action.extract` | 本格有撤离点且已清自己的怪 |
| `duel.leave` | PVP 开打 8 秒内 |
| `duel.escape` | PVP，读条 2s，CD 12s |
| `session.resume` | 任意在线恢复 |

房间下发快照 / 增量：`room.snapshot`、`room.revision`、`map.player_count`、`duel.started`、`duel.ended`、`battle.*`、`player.died`、`settlement.ready`。小地图投影含 Boss 格、泉水格、自己位置和当前地图活跃玩家总数，不含其他玩家位置。

登录：原型本地开发身份；Steam 票据服务端向平台验证。微信 `code` 只留接口。
