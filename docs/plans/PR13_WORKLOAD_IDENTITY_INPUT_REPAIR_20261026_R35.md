# R35 工作负载身份输入遗漏修复与独立复核

R34原始两端协调器均退出0，执行、证据、负载、性能和清理全部Passed；60个原生退出0。原联合裁定停在`workload_identity_mismatch`。发生器实际用20个控制文件与完整2159个客户端输入的并集生成身份；校验器却只用控制文件。两端加入实际原客户端输入后都精确重现原`workload-profile.json`及报告ID。

本修复只把校验器身份输入改成与原发生器一致，不改原contract、原文件、原spec、窗口、阈值或原判定文件。模拟夹具同步采用真实发生器的完整输入形状，增加“只用控制文件不能替代完整定义”的负例。

当前默认审查仍要求运行时来源字节与收集时冻结值一致。对已封存R34另设版本化独立审查工具`tools/pr13_workload_identity_review.py`：要求同一个完整输入的SHA、原失败判定及原采集版本；修复版工具必须来自明确的冻结Git提交。所有其他控制文件保持原SHA；对校验器只允许身份构造及其明确的来源修复管道差异。去除这几项具名修复辅助并还原两处调用后，旧、新校验器的完整AST（包括main、全部阈值和判定函数）必须完全相同。任何其他判据改变都拒绝兼容审查。

独立审查还逐成员核验封存数据，并精确核对两端原始`workload-profile.json`的完整definition，不能只信摘要字符串。原联合失败文件不可覆盖，新的派生结果必须记录原采集提交、复核提交、工具SHA、原输入和原失败SHA、未变判据投影SHA。修复本身新增真实对局0，不借此回算其他历史失败或改变已登记的R33口径。

正式结果仍需准确修复提交的完整CI及冻结后的独立重放；预提交诊断不作正式通过。R34的311份原件、实际另库恢复31场/107结算/64账号、0待处理占用/0重复结算已验证；6个自有停止容器及已验证副本已清理，正式服未清空。容量累计284/300，余16；本修复不重启负载、不重置预算。100人容量及总体仍未通过。
