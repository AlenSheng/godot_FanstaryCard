# Godot CI evidence allowlist

The isolated fixture places Godot settings/data/cache under its output directory. Uploading that entire directory included the automatically generated `http-fixture/runtime/data/godot/keystores/debug.keystore` in old cloud-local artifact 11117902924. Only ZIP entry names were consulted for this fix; key content was neither inspected nor printed, and existing artifacts were not deleted.

The fixture creates a minimal project and copies only named network scripts, test scripts and schema/golden-vector files. It copies no export presets or signing files and invokes import/scripts, never a signing export. Godot 4.7.2's [Android editor implementation](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/android/export/export_plugin.cpp#L866) generates the editor debug keystore when its Java SDK is available. Its [path implementation](https://github.com/godotengine/godot/blob/4.7.2-stable/editor/file_system/editor_paths.cpp#L74) chooses the Godot data directory's `keystores/debug.keystore`. Together with the fresh CI fixture directory and observed default path, this identifies the automatic debug source, rather than a production signing operation. This is source/command/path evidence; no cryptographic inspection of any key was performed.

`tools/cloud/export_evidence.py` stages named reports for cloud-local, Gameplay client and Numerical client. Unknown filenames, runtime/settings/cache trees, keystores, PEM/JKS/P12 files, credentials and fixture source copies are never traversed or read. It rejects symlinked roots/ancestors, leaf/directory symlinks, hardlinks and devices/FIFOs using descriptor-relative no-follow opens. A fresh separate destination is required; existing contents are neither reused nor deleted. Each selected report gets an inventory entry and SHA256. Missing files are recorded so failed fixture diagnostics remain available. Unsafe selected paths make the CLI fail while preserving safe partial diagnostics. The upload step receives a path only after fresh staging was created, and skips if no safe path was emitted.

Non-secret report/log bytes are preserved. Bearer/JWT, explicit credential assignments and private-key blocks accidentally printed in allowed diagnostics are scrubbed. All three workflows stage on failure as well as success. **The final-runtime-image job, its real build/validation logs, image JSON and exported final DLL TRX remain byte-for-byte unchanged in the workflow.** No deployment workflow, guard, application code, account, credential or access permission changes are included.

Local validation: 41 cloud tests pass, including complete report retention for all three profiles, private paths never opened, partial failure logs, symlink/hardlink/FIFO rejection, stale destination refusal, CLI failure propagation and credential-text redaction. Actionlint validates the three changed workflows and existing deployment workflow. A real Godot 4.7.2 fixture passes 173 codec and 24 loopback checks; its four report/log files are preserved byte-for-byte in a ZIP containing only those files and the inventory. The first local run generated no keystore without a configured SDK environment. A fresh subprocess with `JAVA_HOME=/usr` then reproduced automatic default debug generation; only file existence/size/time were checked. Raw-byte comparison caught a harmless `bearer = true` assertion being altered by the initial scrubber; its pattern was narrowed and regression-tested. See [local verification](local-verification.json), [probe history](origin-probe-note.txt) and [test log](offline-tests.log).

This fix is a separate review branch based on frozen candidate `94ab80ebb4585f52d2ba632ba025da0913f08876`. It does not alter the independently retained PR17 image evidence or the unsafe cross-version rollback conclusion. No main/release push, merge, server connection or existing-artifact removal is authorized or performed.
