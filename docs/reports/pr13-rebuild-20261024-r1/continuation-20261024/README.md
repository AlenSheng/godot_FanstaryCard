# 当前版本续验收（2026-10-24 至 2026-10-25）

本轮仍为部分验证，未整体验收通过。GDD、配置包和历史 132 项登记表维持原基准；牧师 80、法师 70、守卫 100 是合法基础血量，测试中的冻结快照哨兵值按快照断言处理。

- 清理前先在 G 盘建立独立内容副本并核对 SHA256，再删除 1,358 个已备份临时路径，释放约 1.82 GB。另按本次允许清空测试数据的指示，删除 44 个未挂载的项目测试 PostgreSQL 卷，释放约 4.60 GB。这部分数据库负载没有逐字节备份，不能归入“已有原件备份”的清理范围。两部分实测合计释放 6.42 GB，现用正式服数据库保留。
- 继续完成测试后，G 盘已逐项验证 1,329 份原始测试文件及 185 份容器／源码元数据，另保存三份本轮数据库逻辑导出；确认后移除 34 个本轮自有停止容器、工作树、临时数据目录和云端大归档。最终云端可用空间约 8.27 GB，正式服健康接口 200，应用和 PostgreSQL 身份、镜像、启动时间及环境摘要未变。
- UI 修复备战摘要遮挡、长说明滚动内容不可见，以及受击反馈被界面重建覆盖。1920×1080、1280×720 的真实离屏渲染分别完成 68 张美术截图和 34 张玩法截图；最终玩法检查 100/100、布局错误 0。两次渲染的覆盖分别对应最终文件，未声称是一轮物理合并的 102 张运行。现场核看了最终滚动说明和受击反馈，现有资源风格一致，未重出美术资源。离线夹具里的无服务器提示不构成在线连接验收；真人体验仍在范围外。
- 法师限定的清场撤离场景通过：10 账号各完成 3 次正常确认结算，共 30 次参与、10 个实际服务端对局，最终无未清占用。全部使用完整原生 Godot，未降低玩法帧率；本项不代表性能或容量通过。
- 50 客户端测试未通过：启动 28 个完整原生客户端后，第 29 个因可用内存不足“6 GiB 保留量 + 256 MiB 启动预算”被拒绝。100 客户端因此未执行并保留未通过；这不能推断云端最多只支持 28 个客户端。原测试截止点的业务清理未知状态也保留，未用后续数据库检查覆盖。

**本次放宽必须随结论一起阅读：** 混合职业原场景先后在 240、480、600 秒观察窗口仅完成 7/30、10/30、17/30 次正常参与，三轮失败原件均保留。最后改用“仅法师 + 清场撤离”才完成 30/30，因此原混合职业目标继续未通过。容量阶段只在自有测试服务上暂提速率配额；云端磁盘门槛从 15% 调到 5% 且至少 3 GB。法师最终周期恢复默认配额；没有改 GDD 数值、合法死亡／撤离判定、原生客户端或本地 6 GiB 保护。

本地全部使用 headless、静音、隐藏控制台、低于正常优先级；容量进程只使用最后四个逻辑 CPU。自有客户端及转发进程已退出，其他项目进程未操作。旧 86/90、130/139 原件缺失、真实 fork 环境不可用及其他历史缺证继续单列，当前结果不替换历史事件。服务端业务、协议和数值配置未修改。
