## 100人测试的正确归类及CPU调整

100人方案仍为SJH50、本机30、云端20。最新批次实际启动SJH45、本机30、云端20，共95个官方原生客户端；服务器房内人数原始采样峰值76，尚未形成有效100人共同窗口。**该批次的NotPassed是测试批次未完成目标的记录，最终按发生器供给与单机测试停止条件受限处理，不作为已确认的服务器100人并发承载缺陷；也不宣称100人已实证通过。** SJH停止时的45个客户端数不是服务器容量上限，也不是已经证明的机器固定并发上限。

SJH由仅允许逻辑CPU 20、21、22、23共4个，放开为逻辑CPU 0至23全部24个；仍为BelowNormal优先级，只调整本任务监督器及子进程，内存保护不变。旧4核批次与新24逻辑CPU批次分别封存。

最新批次SJH监督器连续三窗观测到HTTP P95为6906、8718、6560毫秒，命令P95为13931、12343、11803毫秒，触发保留的5秒/8秒停止阈值；本机及云端随后联动停止。此停止记录反映测试链路上的端到端观测，没有把客户端调度、传输与服务端耗时分别隔离，不能据此归因为服务器并发能力不足。

原始SJH退出码3、28个强停PID、28份缺失原生终态及原cleanup=false均保留。本机、云端原退出130，原生终态完整，无强停。后续已完成物理清理，不回写原失败维度。旧最后一轮50人测试的延迟停止及15个强停记录也保留，不因已有50人通过轮而覆盖。

CPU调整、各机原始终态与收尾详情见[24逻辑CPU批次报告](<G:/Program Files/GodotFiles/godot_FanstaryCard/docs/reports/pr13-rebuild-20261024-r1/continuation-20261025/R39_CPU_UNRESTRICTED_20261027.md>)。其中100人未通过表述按本节解释：有效100人验证未完成，服务端100人承载能力未形成可判定结果。
