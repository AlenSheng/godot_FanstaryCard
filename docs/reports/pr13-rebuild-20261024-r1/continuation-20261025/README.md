# 当前版本续验收：周期、真实容量与清理（2026-10-25）

三职业正常周期功能回归通过：4 法师、3 牧师、3 守卫，10 个账号各完成 3 次正常结算确认，共 30 次正常参与、15 个实际服务端对局。执行、证据、功能负载、玩法及进程／业务清理均通过，最终无待处理资产占用。整体仍未验收通过，50/100 容量及其他未决范围继续保留。

**本轮明确放宽了观察窗口：从每周期 20 分钟提高到 40 分钟。** 职业、账号、每账号 3 次正常结算、原始循环路线及全手出牌策略保持原范围，未修改游戏数值、伤害或死亡／撤离规则，未降低原生客户端帧率。20 分钟轮次的 24/30 失败原件保留。30 次观测中有 3 次从入房到确认超过 20 分钟，最长 2,065.844 秒，因此本结果只通过正常周期功能，不声明默认局时长或性能目标通过。

原始记录中 `room.started` 的部分周期编号是 `Unknown`，原件未补写；时长按同一客户端与权威 match_id 对应的入房、确认时间计算。正常结算次数仍采用原协调器的审计重放结果，弃战降级与清理阶段确认不计为正常周期。

310 份原始文件及数据库导出已传回 G 盘并逐项验证 SHA256；另在全新的隔离 PostgreSQL 验证库实际恢复，15 对局、30 结算、0 待处理占用与原库一致。旧测试容器、网络及已备份临时目录已回收，完整源码工作树原样转移用于后续测试。正式服应用与数据未参与本轮清理或恢复，健康接口保持 200。

50 客户端实测已执行并保留未通过：本地 25、云端 25 个完整原生客户端达到过 50 人，但两端持续活跃覆盖率分别约 59.79% 和 43.34%，低于 95%。云端审计缓存误用 128 MiB 内存临时目录，Windows 快速时钟探针出现重复单调时钟刻度；完整原件已收回重放，原失败报告未改写，未把瞬时峰值当容量通过。

随后另行预先声明了更大压力的 **60 客户端、至少 50 人持续在房间内活跃** 场景：本地 32、云端 28，分别要求至少 27、23 人活跃。它与原 50 客户端场景分开判定。审计缓存改到自有磁盘目录，时钟探针间隔 40 ms；完整引擎、原始路线、游戏数值、帧率及原资源门槛保持原值。实际两端 720 秒保持窗口覆盖率为 98.69% 和 98.77%；按原始时间探针保守校正后的共同 600 秒窗口，至少 50 人活跃覆盖率为 100%。合并原始运行期请求为 HTTP 1,381 次、实时请求 54,958 次，P95 分别为 1,129 ms、587 ms；不是平均各端 P95，也不扩展为整个正式服 SLO。

**本轮容量整体仍未通过。** 两端原协调器的执行项均失败：3 个客户端有 4 次出牌拒绝，3 次提示决斗不活跃、1 次提示眩晕不能出牌；证据、负载、性能及清理项通过。GDD 基础卷 §3.2 明确 PVP 眩晕不能出牌。原始发包记录显示，这些请求属于当前房间与本地战斗，眩晕值为 0；收到决斗不活跃的几次，本地快照仍是 PVE。精确服务端执行时状态未观测，不能只凭错误文字认定服务端规则异常，也不能直接认定时序原因已证明。未新增错误白名单、未放宽执行失败项、未将本地快照冒充执行时状态。原失败保留，100 客户端阶段仍未执行，不由 60 人峰值推断服务器容量上限。

R5 随后增加外置只读执行状态观察器，未修改服务端业务程序集。Windows 和同一正式镜像的 Linux 受控验证各通过 34 项，包括真实本地 WebSocket／路由器／actor、错误关联拒采及观测不改状态。初次按源码私有名称查找失败，随后依据实际混淆程序集的元数据、异步状态机和串行调用栈绑定；失败原件保留。该阶段所有尝试合计 21 次受控模型房间执行、42 次模型玩家执行，无实际注册账号或自然对局；确实执行过受控本地 HTTP／WebSocket，不能称为完全没有网络/API 调用。

**R5 实际 32+28 客户端复测仍未通过。** 达到过 60 人后，本地一次健康探测耗时 5,004.14 ms，资源监控缺失，按原始证据规则在共同窗口前停止；相邻云端探测为 4.36 ms、CPU 约 71.28%、可用内存约 729 MB。错误文字中三次 `monitoring_unavailable` 是多个缺失字段，不是三个连续采样。原退出和失败状态保留，不认定服务端宕机，也未证明传输或本地调度的具体根因。新采到的 11 个队列内校验异常已与实际请求、玩家、房间、调用栈及完整状态摘要逐一核对：7 次出牌时指定卡牌确实不在权威手牌，4 次放弃时权威状态已为 Choice／PVE Cleared。观察器无内部错误或丢失，完整状态经同一 Domain DLL 的类型化序列化重算摘要及语义核验。它证明本轮拒绝对应的执行状态，不能单独证明意图为何过时，也没有补回 R4 的旧四次现场或放宽原失败项。详见 [R5 执行状态及失败结果](execution-observer-r5-notpassed.json)。
