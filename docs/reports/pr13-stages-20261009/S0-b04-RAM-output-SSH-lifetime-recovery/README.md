# B04 RAM输出跨SSH会话保留修正

第一批RAM计算和原验证器成功，但SSH断开后 /dev/shm 中UID1000的原生文件已缺失，G归档只含7份剩余元数据和空容器日志。该批不计入完成数，实际仍313/540；原systemd结果、日志、残存归档和失败记录全部保留。

仅执行40字节存储探针，未重跑业务：同一SSH会话中 /dev/shm 和 /run 的文件在容器删除后都存在；关闭该SSH再从新连接观察，/dev/shm 文件已消失，/run 文件仍存在且SHA相等。logind配置含默认RemoveIPC=yes注释。这证明实际会话生命周期差异，不将原件缺失误写成Docker删除失败或游戏失败。

新冻结控制器使用 /run 的专属tmpfs输出路径。采用313批已有完整G原件，540批完整矩阵、256 MiB输出预算、额外RAM预留、500 MB内存底线和15%云盘底线保持不变。缺失的首批以独立记录的恢复尝试重采原场景，不覆盖旧失败或伪造归档，不将两次计算计为两个独立样本。原件完整G校验后才推进下一批。
