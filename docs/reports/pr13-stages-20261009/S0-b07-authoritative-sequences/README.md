# S0 护盾余量权威序列实验

前一轮已完成玩家说明，B07.3 业务 EXPERIMENT/RENDER 仍未覆盖。本轮将实际 BattleRoom/CombatDeck/Resolver 的序列输出保存为可复核原始证据，并用于后续 Godot 渲染；不使用说明文本或手写客户端数值替代权威状态。

固定当前 release 与 Domain 源码，默认 CurrentSteps 和候选 FractionalRemainder 分开，同预算、同可见输入和配对 seed。每个 +0～+5 等级使用三个互不重叠种子块 200001、201001、202001，每块 1000 配对 seed。固定每次五张成功的护盾牌，预览、非法目标/版本、已经消耗实例的重复出牌，上限的满盾/零盾/精确补满/溢出，以及 JSON 快照、PVP 生存返回和合法地图离格。

主要指标测前固定：五次武器贡献、预览/拒绝操作的完整状态副作用、余量/上限黄金值和冻结快照恢复。按 seed 配对给出 95% 描述性区间；控制合同必须零违例，不据此推荐生产启用候选。六个等级单列，原始失败不能删去。单作业上限 420 秒、三作业总上限 1260 秒、单并发。全量原始记录压缩保存并核对压缩/原始 SHA 和字节数，有限动作不靠延长观察期通过。

这是明确边界注入的权威序列实验，不能冒充完整探险路线、正式玩家网络操作、PVP 胜率、准备后 Boss 或容量。生产候选默认关闭，暂缓严格失败和容量，真人体验不在范围；内存 500000000 字节和磁盘 15% 安全线保持。

足量实验前的原生预检完成 36 行，原始 5694366 字节、零错误。按实测密度，1000 seed 的原始单文件约 1.9 GB，超过既有 512 MiB 单文件验证上限。因此在启动足量实验前固定物理分片：每个原逻辑种子块拆成五个连续 200 seed 文件，共 15 个物理作业。每档仍为原来三块×1000 配对 seed，不增删种子、场景或动作；每个逻辑块所有分片合计仍不得超过 420 秒，三块合计仍 1260 秒。此项调整只解决完整状态保存的文件边界，不改变判据或借延长观察期通过。

预检压缩文件 450633 字节，足量数据预计约 450 MB，而云端磁盘在 15% 安全线以上只有约 60 MB。因此使用明确归属的 /dev/shm 临时内存目录保存原始压缩数据，上限 768 MiB；运行内存仍逐次保持 500000000 字节安全线。元数据、命令和结果持久保存到任务证据目录，全量原始文件下载本地并核验压缩/原始 SHA 和字节数后才允许回收临时目录。统计与原始校验仍在云端进行，本地仅收集/复核证据，不运行业务服务器。
