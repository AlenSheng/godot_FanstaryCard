# B09.1 当前怪物卡池基线 OFFLINE

以三个职业的合法默认 20 张卡组进入真实房间，覆盖 21 类怪组和宝箱怪六种元素。受控边界只将原怪物留到最后一点生命，实际 PlayCards 使用本玩家可见手牌完成击杀；它不代表自然完整战斗或合法探索路线的结果。

20 项领域检查和 9 项服务端协议检查通过，没有跳过。原始数据含 234 条默认策略检查、315 条逐击杀来源检查、27000 条逐种子的 native 弃牌洗牌/抽牌观察；18 条原始 Protobuf 快照又由 Godot 解码并核对。独立校验器核对来源、实例、合法基础牌与牌面伤害，并拒绝四类损坏数据。

当前配置保持自动加入怪物卡，可选吸收策略仍关闭。默认快照不提供 monster_pool，也不允许 monster.choose；隔离候选快照的实际 pending、牌堆数量和允许操作单独核对。Proto3 省略空可选列表的既有语义保留；协议检查比较怪物卡池、牌堆、操作及完整二进制重新编码，未将与本检查无关的空列表/null 约定改成生产规则。

真实自动加入的两张火蝠卡提高了原始牌面伤害总量，但在冻结的 native 洗牌控制中，各职业/房间种子的关键牌 C01 平均到手序号均延后。逐种子的第二张火元素到手序号也保留，两种效果没有合成“卡越多越强”的结论。这是 OFFLINE 的构筑稀释反例，不能代替完整战斗、路线收益或真人体验。

完整原始归档存 G 盘并校验成员、gzip CRC、原始 SHA 和数量后，才清理本次通过的云端输出链接。前四次权限、静态检查、依赖缓存及协议断言失败记录保留。已经通过的领域原始数据和测试日志复用，领域源码等价另行验证；原始执行 SHA 不改写为新 SHA。

完整 EXPERIMENT 与真实画面 RENDER 尚未完成，依赖和整体验收状态保持不变。此前严格网络与容量失败继续暂缓，正式策略和卡牌数值未改变。
