# B09.2 客户端协议双向核对

云端原生服务端生成 279 条选择场景及 558 个实际前后快照：144 条未满接纳、81 条满位替换、54 条跳过。Godot 读取原始 Protobuf，核对容量、待选和已吸收实例、手牌顺序、牌堆数量、可用操作及实际 Game 意图校验。随后 Godot 重新编码 279 条命令，服务端逐条解码，按房间／请求与原始命令关联，验证完整类型化等价；重复或缺少的原始记录不能通过。

36 项服务端生成及原有协议回归检查通过，回程检查 1 项通过，均没有跳过；本次回程明确使用 279 条实际 Godot 输出，没有使用普通 CI 的原生回退检查。领域 OFFLINE 的 47 项检查仍在上一份报告中，两组执行 SHA 分别保留。

第一轮客户端有 198 条意图断言失败：测试把解码补出的空替换字段直接作为 UI 意图，而原界面不携带此空字段。只修正测试输入层次，保留已通过的服务端生成、原始快照和全部失败记录；原生业务、协议及正式客户端逻辑没有改。后续 Godot 与服务端回程使用已有只读原生构建，逐文件确认源输入等价。原始数据 SHA 不改写为客户端修订 SHA。

本机上传工具因内存不足失败，计划和客户端测试修订通过已连接 GitHub 接口上传。首个发布提交与原始执行提交的整棵源码树相同，提交身份分别记录。原始执行提交也随 10 KiB Git bundle 保存到 G 盘，可以从既有公开前置提交恢复。当前客户端修订与原始服务端输入等价另有核验。

98 个归档成员、gzip CRC、原始 SHA 和数量已在 G 盘核验，才清理第二次通过的云端输出链接。第一轮失败原始证据、原生构建和正在运行的 B08.4 输入保留。整体验收、完整收益实验和实际画面验收仍未完成。
