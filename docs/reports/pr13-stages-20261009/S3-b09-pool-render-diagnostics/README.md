# B09.2 怪物卡选择界面诊断与布局修复

真实云端 X11／Mesa 界面复现了弹窗高度异常：在英文 960×540 的 8 位满容量场景，逻辑窗口被自动换行文本撑到 787×2290，实际弹窗图像为 394×1145，超出主窗口。文本进入容器前没有可用宽度，换行最小高度被提前累计。为现有容器和文本设置明确可用宽度，并让已吸收名称和卡牌描述自动换行后，窗口降为 680×618，实际图像 340×309，完整落在主窗口内。

守护者、8 位满容量、英文窄窗口的一个实际原生替换边界通过。从正式探索入口打开对话框，实际鼠标展开下拉项并选择第一张已吸收实例，吸收按钮由禁用转为可用；实际命令与原生 Protobuf 相同，原生回包前状态保持不变，应用原始回包后正确展示新卡池。对话框关闭且实际渲染进程正常退出，无 ObjectDB／资源残留告警。强制一帧解析进程的退出告警另存，不作为正常退出证据。

前五轮解析、窗口路由、旧对象记录和布局失败的原始日志及画面都保留。成功打开的窗口在正常关闭后释放，最终检查保存的是先前打开事实，不再把释放后的引用当作打开失败。事件仍走正常鼠标输入和控件命中路径，未直接发 pressed 信号或调用选择回调。

原生快照和前后候选来自既有领域和协议边界，回应延迟、请求头属于明确的界面测试投影，不能代替真实公网、客户端登录、完整自然路线或多人容量。窗口输入和坐标依据 Godot 官方 [窗口事件](https://docs.godotengine.org/en/stable/classes/class_inputeventfromwindow.html) 与 [坐标变换](https://docs.godotengine.org/en/stable/tutorials/2d/2d_transforms.html) 合同，实际输入轨迹原样保留。

完整画面矩阵已冻结为 27 个职业／容量／用例单元，五种现有语言、三档窗口、三档帧率上限、三档受控回应延迟及三个原始种子边界。首个守护者 8 位满容量替换单元已启动，要求 405 条观察和 45 张图；这一界面 fixture 矩阵不宣称已经完成同一真实账号的多局验收。全部要求仍以完整交付证据为准。本诊断只签一个边界，不能升级整项 RENDER 或 MAIN。

六轮原始归档的 69 个成员和五张 PNG 已核验存入 G 盘，才清理通过的第六轮云端输出；失败原始证据、当前矩阵输入和 B08.4 实验均保留。
