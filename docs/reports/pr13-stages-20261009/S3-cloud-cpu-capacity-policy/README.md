# S3 云端实际 CPU 容量配置

上一轮 50 个实际客户端启动完成，但在线／活跃采样最多 12 人，发生登录／数据库超时和命令拒绝，未通过。实际 PostgreSQL 专属实例只有 0.3 核，累计 CPU 节流 182349971 微秒；服务器日志出现 Npgsql／超时异常。应用及数据库没有 OOM，峰值分别约 147／215 MB。该证据指出资源配额影响，不据此单独断言全部失败根因。

新配置允许专属应用与数据库直接共享实际宿主机 CPU，启动后核验两者 NanoCpus=0；宿主机 CPU 85% 停止线保留。应用／数据库内存预算保持 512／384 MiB，宿主机及发压器可用内存停止线 500 MB。每个真实客户端启动间隔改为 3 秒，50/100 人数、600 秒窗口、95% 覆盖、120 秒连续和 2400 秒总截止保持。北美 5／8／10 秒延迟基准不再调整。

本次只改控制器及授权保护，腾讯云聚焦回归 5/5 通过；之前 71 项策略回归回执保留。禁止在未开启专属测试身份时移除 CPU 配额。实际新配置和容量必须另跑验证，生产配置保持原值。
