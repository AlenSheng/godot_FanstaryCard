# S3 结算通知后的客户端房间操作保护

结算通知到达后，原客户端仍保留上一份战斗快照的可用操作，异步获取回执期间可能再次出牌或读取旧房间。现在匹配当前对局的有效结算通知会立即关闭这些操作。终态权威快照也会关闭操作；回执查询或确认失败、同房间较旧快照返回均不会重新开放。进入新房间或重新认证会释放对应的旧上下文保护。待结算回执仍可自动查询和手动重试。

保护绑定会话代数、房间上下文 epoch、match 和 room。旧对局通知与缺失回执编号的通知不能关闭新房间。排队操作、目标切换、待确认指令和预览会在终态清除，不把这些操作重新发到新房间。不会把拒绝写为成功，不修改 Lua UI 自动注入绑定或职业数值。

真实腾讯云、网络隔离的 Linux Godot 完成 18 组客户端回归。新测试 22 个检查全部通过，包含暂停回执获取、查询失败、同房间旧快照、确认失败、新对局隔离、无效通知、终态快照和重新认证。另对发压脚本执行实际解析与观察预算检查；死亡和撤离完成事件新增原始顺序、版本、玩家和线报房间标识记录，缺失标识显式保留。新增日志不延长无进展停止时钟。

将实际提交的四个 Git 源码字节与云端执行输入逐一核对；使用 LF 发布字节独立复跑 18 组回归和发压脚本解析，退出码均为 0、脚本错误 0、运行前后输入不变，专属容器已清理。原先 Windows CRLF 输入的通过结果仍保留。两次冷导入超时和一次准备阶段磁盘不足均保留，未执行的断言没有记为通过；一般 Godot Variant 输出采集失败也单独记录，原始输出未修改。

497188 字节私有档案已下载并核对全部 9 个一级文件；其中原始档案的 21 个输入、日志和故障文件也已单独下载核对。公开汇总只提供范围、检查结果和哈希。

本修复不能撤回结算通知到达前已经发送的请求，也不证明 S5 原有 32 条拒绝均已解决。后续用实际本地客户端连接当前云端版本复测，完整保留死亡、撤离、结算与指令顺序。原 S5 失败记录、50／100 并发、真实公开 TLS 和最终全范围验收仍独立处理。
