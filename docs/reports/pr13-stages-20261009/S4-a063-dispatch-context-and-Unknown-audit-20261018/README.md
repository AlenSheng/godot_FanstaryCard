# A06.3 请求发起上下文与Unknown审计

本地实际链路为Gateway遥测→Game信号→原负载记录器→原审计落盘。两种传输各完成修正后8项检查；三个规范案例在修正前也已通过：cycle1发出、cycle2回包仍标cycle1；429／Retry-After 1秒重试期间stage切到settlement，attempt与终态仍为原playing且logicalID相同；真实STOP文件被_process看到后，实际到达时钟属于drain，业务phase仍保留playing。**保留旧业务phase是正确行为，不把它误报成应改为cleanup。**

原整轮未通过的原因是额外必要控制：记录器用当前run_id／client_id／process_epoch覆盖事件中已冻结的来源身份；异步来源缺失时，cycle／phase回填当前值。真实网络延迟控制复现了两个问题，两个原臂及原件均保留。仅本地修改gameplay_load_client.gd的上下文区域：优先保留已捕获来源，收集者身份单独放observer_context；缺失异步字段标Unknown并列缺失字段，已知无room／match的空字符串保留；本地同步生命周期事件仍用本地上下文；到达属于drain单独记录，不覆盖原业务phase。null来源元数据的声明诊断回放也通过，不计为新的HTTP请求。

初次修正候选因Variant表达式缺显式bool未加载，HTTP为0，进程在45秒上限被终止；原候选／错误未删除。3次编译诊断定位后修正声明，计入原8次启动预算。一次CIM查询被拒后未重试，其空返回不当作进程不存在证据；使用基础进程查询及实际终态句柄复核。实际完整实验4臂＋零HTTP加载失败1次＋编译诊断3次＝8／8；总36次HTTP≤160，没有限额或正确性放宽。修正后两臂退出0，engine／stdout无脚本或资源错误，所有夹具线程与socket关闭。
