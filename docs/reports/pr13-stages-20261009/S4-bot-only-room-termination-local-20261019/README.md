# 无真人机器人房间终止：本地修复与验证

修复零真人房间仍继续模拟的问题。旧判断遇到真人数量为 0 会直接返回；现在统计仍活动的真人，交给既有 `BotRules.ShouldEndRoom` 判断，沿用原有机器人退出和战斗清理流程。依据为 `SERVER_SPEC.md` §5.1，GDD v0.70 的优先级及牧师合法 80/70 显示不变。

新增 5 个 Domain 用例。旧代码实际执行后 3 失败、2 正例通过；失败覆盖纯机器人 PvE、恢复后缺失最后真人、纯机器人决斗。修复后相关 Bots 40 项、Server 10 项全部通过，无跳过、超时或强制终止。原机器人 AI 测试增加非战斗真人以维持房间寿命，原有 33 条断言均保留。

新增 Server 用例实际启动一个本地 PostgreSQL 测试对局：房间首个 100ms 权威 Tick 触发结算观察器，2 个机器人成员进入 Settled，对局进入 Completed；重新创建观察器后重放，不改变首次结算时间。11 张玩家、资产、奖励、账本及遗物表保持 0 行。临时测试 schema 已释放，本任务 PostgreSQL 正常关闭。

依赖仅来自冻结的本地 NuGet 包，使用 SDK 10.0.400。共执行 3 次托管测试，已通过项未重跑。依赖恢复前的辅助脚本曾因 TEMP/TMP 共用目录初始化失败，发生在 dotnet 启动前；修正后原失败目录保留。新增本地对局预算为 1，单独预登记，历史容量 600 场记录不变；本项没有上传、云端测试或部署。

本报告仅证明上述本地生命周期与 PG 结算闭环，不证明 HTTP、客户端、并发容量或后台自动移除房间。旧运行包早于本次改动。原 100 客户端失败与 9 条未确认记录保留；132 任务 / 396 案例范围不变，不修改 register、gate 或 MAIN。逐案例结果与证据 SHA-256 见 summary.json，原始日志、TRX、源文件前后副本保留在 G 盘本任务证据目录。
