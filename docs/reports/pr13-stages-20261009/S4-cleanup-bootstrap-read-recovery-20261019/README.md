# Native 清理核对的短暂读取失败恢复

清理探针收到第一次 bootstrap HTTP 500 后立即结束核对，未继续使用原有观察窗口。现在对已解码的 500/502/503/504 读取错误，在原 22 秒窗口内最多额外发起两次只读查询。每次请求前后检查会话、局次、准备单和票据；重试等待中发生切换也会停止。

只有完整权威状态确认业务已清空，才能记录 Passed。持续错误、鉴权失败、解码失败、上下文变化或未确认 receipt 均保留 Unknown。ACK 继续沿用现有流程；原始 HTTP 错误仍进入原采样，新增重试事件不增加自然完成周期。新增计数对应清理控制器对 gateway.request 的调用，不代表底层传输 attempt；单次网络调用继续遵循 Gateway 原有 deadline。

本地实际 Native 的 4 个套件共 62 项检查通过，未发生引擎错误或强制结束。原源码在相同的 23 项核心反例中有 15 项失败；另补充 6 项计数与会话切换检查，三个相关套件共 33 项同时通过。后端和 ACK 使用明确的合成响应，没有新建账号或世界。完整 17 套件仅完成注册和静态核对，未整套复跑。

历史 100 客户端实测仍为预算停止、9 条未 ACK，原报告及验收状态保持不变。此改动提供本地清理控制流证据，实际 PostgreSQL、容量与服务端连接超时问题仍需独立验证。
