# 清理查询返回值的实际协议边界

Gateway 的分页验证失败和传输失败可以返回不带 data 的失败字典。实际本地 Protobuf 分页反例确认，直接访问该字段会触发脚本错误。清理探针现在通过字典读取接口判断返回值；缺失字段继续记录 Unknown，不发起额外读取或清空待处理状态。

4 个本地 Native 套件共 65 项检查通过，其中新增三个最小返回值反例。实际 Native、GameStore、Gateway 和 HTTP/Protobuf 链路的 7 个合成后端案例、23 项检查也达到预期：两个恢复案例记录 Passed，持续错误、坏消息、401、分页失败和断流这五个负例保留 Unknown。全部进程正常结束，最终检查无引擎错误；旧版本的实际缺字段错误记录单独保留。

42 条实际采样进入原有 Python 审计与统计器，14 条逻辑 HTTP 事务和 16 次传输尝试与对端 X-Trace-Id 一致。7 条错误和 1 条取消均保留，只有一条合成 ACK，且归于 drain；自然完成周期为 0。ACK 内部回读让控制器三次 GET 对应实际四次 GET，两个层次分别记录。分页反例的原 HTTP 200 样本也保留，业务验证仍为 Unknown；本地结果 status=0 不作为零延迟或成功。

本轮没有真实账号、数据库世界或云端调用。后端及 receipt 为合成数据，不能证明真实 PostgreSQL 资产确认或正式容量。原 22 秒核对窗口与最多两次额外读取保持不变。完整 17 套件未整套复跑；历史 100 人失败、9 条未 ACK 与正式验收状态保持原样。
