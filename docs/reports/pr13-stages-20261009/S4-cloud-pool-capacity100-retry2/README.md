# S4 北美延迟基准下100客户端第二轮复跑

预登记维持100人目标、600秒窗口、95%覆盖与120秒连续要求，HTTP P95 5秒、实时8秒、健康检查10秒；本轮监测查询超时单独登记为10秒。临时测试HTTP/IP/实时准入限额关闭，应用复用池与物理数据库连接上限256，应用和数据库CPU配额解除。

实际只启动42个本机真实Godot客户端，最高观察在线38、活跃32。下一次启动前触发本机内存保护，退出3，尚无正常自然周期；原始延迟、命令拒绝、业务失败、停止后进程失败与外围监测缺失均保留。这轮不能证明100人容量通过，也不能据此判定云端容量上限。

可用内存最低要求为500,000,000字节，单次启动另预留64 MiB，总启动门槛567,108,864字节。协调器未记录触发瞬间的确切可用字节数，明确登记为空，不能用相邻采样推算。

原始报告的进程、业务清理及cleanup维度均未通过，保持原值。后续独立云端只读对账确认冻结资产0、活跃匹配0、结算40、流水0，四个专属服务按完整身份移除；这一补充清理证据不回写原轮次维度。完整客户端记录、原始报告、云端归档及哈希保留。
