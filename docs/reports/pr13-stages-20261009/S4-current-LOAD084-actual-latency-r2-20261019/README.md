# 真实请求发现第一版重试回退，收窄自动调度后重新通过

第一版候选虽然20套341项原生回归通过，但真实Program/PG请求证明它也阻止了显式重试：单项响应被延迟1800ms时，原逻辑约121ms恢复，第一版1850ms；丢弃真实单项响应时，原逻辑105ms、第一版3517ms。这个回退完整保留，第一版不作为合格候选继续。

第二版把条件仅放在GameStore._process自动调度处；显式retry_settlement保持原有Bootstrap查询和单飞行为。新增负例同时复现原版“后台重复Bootstrap”和第一版“显式重试被挡”，两个负例均按退出1留档。第二版14项定向检查及20套343项原生检查通过、退出0且双日志干净。最初负例夹具未暂停无关client-info重连而访问了不完整mock，原SCRIPT ERROR和源文件保留；只修正测试时钟并使用新输出目录，没有重跑真实场次。

真实第二版正常自动恢复与原版均约67ms，Bootstrap为1次对2次；显式重试在单项响应迟缓/丢失时，分别138ms/122ms恢复同一实际收据。迟缓/丢失只施加在真实后端回复上，状态、字节未伪造。测试使用现有真实未ACK就绪收据，16玩家/8局/32收据/31ACK以及八类资产摘要完全不变，新账号/局/ACK写入均0。

这些是已知ID恢复组件的真实请求控制，含声明的客户端恢复上下文，**不是完整每局收益验收**。LOAD08.4-T01/EXPERIMENT保持缺失，60项Accepted、72项未验收、266个案例/层级缺口不变，没有NoChange、放宽阈值、推送或部署。下一步为当前baseline对第二版的三轮完整同负载配对，先冻结新增预算和设计；原8场补测及B11121/B11227预算不重置。
