# LOAD-08.2 当前GET合并成对实验

3个案例的当前EXPERIMENT层通过：6组成对比较、12个原生Godot实验臂，覆盖per-request／reusable传输与2／4／8个调用方，关闭合并的基线和当前版本交错顺序。基线仅在本地测试覆盖层为GET指纹增加唯一后缀，原request_page函数其余内容逐字一致；当前臂使用原工作区Gateway。没有修改或提交产品代码。

相同28次调用方读取，基线发出28次底层GET，当前版本发出6次，少22次（该合成混合场景78.57%）。这证明设定并发场景的请求合并；不推成正常游戏流量、时延、WAN、TLS、TTI或容量收益。每臂还检查真实404共享、64位最大整数、256／16384／98304字节未知字段填充的完整二进制体，以及一位消费者修改结果后其他副本不变。共220次原始响应／POST字节哈希核对。

写后旧响应使用当前GameStore与Main原购买回调：实际线序为写成功→新读99900→迟到旧读100000→自动刷新99900；12个臂可见钱包变化均仅[99900,99900]，新读没有合并到旧版本。每臂两玩家、不同参数、不同服务地址均各发2次物理读取；并发重复写实际仅一次发出，另一次明确失败，未伪装共享成功。均为声明的内存夹具数据，无真实资产断言或真实账号／对局。

12个正式臂均退出0，engine与stdout干净，所有夹具线程和socket关闭。初次夹具控制把PurchaseShopRequest写反，5次合成请求后失败；第一次原生解析因SceneTree入口无法访问Game自动加载而失败。两者原代码、日志保留，修正后的12项夹具控制及标准Node场景解析通过后才执行正式矩阵。总14次原生启动≤16，含失败控制共208次合成HTTP≤300；未放宽限额或玩法／资产正确性。

历史真实PG源2ddf347的request／request_page等函数相同，但request_http_transport有差异；行结束符差异已单独处理。旧PG结果保留原SHA及适用范围，不宣称当前完整PG重新通过。本轮仅补LOAD-08.2-T01／T02／T03的EXPERIMENT证据，任务仍Partial，前置TLS等其余profile／集成仍待验收。canonical register／gate／MAIN及132任务396案例范围不变，正式剩余77项。
