# LOAD-11.2 归档来源与分块路径误关联修正

本轮全部在本地执行，未新跑玩法、统计、UI或云任务，未改正式产品源码、资源、GDD、旧报告和验收状态。完整GDD主卷v0.70＋基础卷v0.69原字节核对，合法80/70仍保留。132任务396案例范围不变；官方55 Accepted／67 Partial／10 Ready，77项未验收，LOAD-11.2仍Partial。

原185条未证明版本中，索引有173条同hash候选；本轮没有据此直接认定来源，而是逐项补来源角色、完整路径、封存回执和实际字节。66条工具源码由记录的源码hash表＋同回执内完整规范路径快照＋当前文件SHA／字节共同支持，角色映射和封存资料本身也被核对。它们证明保存的字节版本，不证明历史运行一定用了某一副本，也不假称有明确复制命令。

62条导入侧车的原清单声明了Git版本，列有2054个相对成员。枚举该版本中全部13个project.godot根，只有client根完整覆盖全部2054个成员路径；其余根均不满足完整覆盖，未按最高匹配比例挑选。目标元数据在该推定命名空间的Git原始blob／明确检出变体与预期hash、字节吻合。这里明确是完整路径矩阵支持的唯一根推定，不称显式复制来源或历史运行证明；不会据此通过整个客户端集成。

**纠正44条旧读取器误关联。** B07原始备份清单记录了seed_start、name、remote和relative，name只是分块内文件名；旧读取器将它当成公开汇总目录下的路径，把15个分块的原始manifest／summary／render-vectors的hash拿来比较同名公开汇总。这是解析错误，不能继续称原件损坏。新读取器只在完整已知schema下使用relative，并要求种子、文件名、远端父目录全部一致；矛盾字段直接拒绝，不退回basename。

局部路径绑定还核对了整个75成员集合：候选本地根必须同时满足全部75条完整relative路径、hash和字节，随后重新读回477505126字节，全部吻合；不是只选44个看似有利的成员。修正读取器又对实际44条逐条验证，先得到正确远端分块语境，再接本地归档证明，不再比较公开汇总。旧输出和旧源码仍保存，但这些44条已明确撤销为schema误关联。此前6619是旧规则候选记录，不再声称全是实际当前文件差异；其余6575条保留原差异和历史语境，仍不自动通过。

另1条统计准备脚本找到已保存的before-stage版本：前后manifest的原生源身份、scope、36000要求及未变的statistics.py一致，归档阶段名匹配，旧原件与当前源码各自SHA／字节吻合。该版本与当前不同是已记录的准备修订，不重跑统计，也不把它说成当前原生运行通过。

剩余79条另外检查了UTF-8签名／LF／CRLF变化，实际读取12个目标共2196821字节，没有新增可重建结果，未删内容或强行匹配。最终剩12条：服务端旧源码6条、旧工具源码1条和旧验收报告5条；已查索引和可达同路径Git未证明这些字节，但未宣称全部备份／不可达对象都搜尽，更未推断为玩法错误。相关SDK缺失控制资料明确不证明业务运行，历史报告也不改签。

当前相关控制为修订后lineage15、custody8、encoding3，共26项通过；其中13个旧lineage控制因schema代码实际修订而回归，新增不同控制13项，不把历次6／8迭代重复加总。未重跑完整122万引用扫描、旧14项公共证据、20项Linux或任何已完成游戏／统计。无场次／正确性阈值放宽，原失败和不同性质的推定、重建、封存版本标签保留。

当前12条版本缺口、其他326489项根／schema／archive关联、6503份未识别引用清单、2175份非摘要隐私类型及完整seed／flags／hardware／region／selector联结仍未闭合。不能仅因多数原件找到便接受整项。新schema修正与这些旧计数必须按来源逐项联结，不能随意扣减不同集合。
