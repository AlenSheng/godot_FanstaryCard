# LOAD-11.2 协议schema、缓存角色与工作簿只读检查

本轮补齐此前220份协议记录与1份工作簿的检查层次，并验证29份真实缓存文件的导出限制。完整范围仍132任务／396案例，官方55 Accepted／67 Partial／10 Ready，77项未验收；LOAD-11.2仍Partial。没有新对局、统计、OCR、UI渲染或云端运行，没有放宽阈值，没有修改产品源码、资源、旧报告或register／gate／MAIN。

协议检查读取实际gateway事件／命令映射及realtime schema。220份原件SHA逐一匹配，解码61571个已知字段节点，扫描8427个字符串字段，未知字段0、不透明bytes字段0、凭据模式与敏感字段候选0。配置包的32字节content_hash按其哈希角色处理，不再误当不透明凭据。这里只证明已有编码字段的覆盖与模式检查，不证明历史网络执行、标识符来源或完整隐私安全；不发布解码载荷。

唯一ConfigBundle含13张表、1599行、16878个值，初查把1308个空ConfigValue标成单值缺失。查项目文档和源码后确认：ConfigCompiler写false时保留空消息，ConfigBundleReader默认false，已有Compile_PreservesFalseLogicalValueAsPresentEmptyMessage测试明确覆盖。按实际ConfigColumn.value_type逐项核对，14735个显式类型值、835个显式null、1308个合法逻辑false，剩余类型问题0。该疑点属于检查器误报，不是产品异常；保留初查记录。合法80/70的协议控制也保持80/70，未钳制血量。

29份历史fontconfig缓存全部重核原SHA，并把各自真实路径交给当前公共证据导出器，均在读载荷前按private/runtime规则拒绝。原件保留，二进制内部语义仍未验；“不允许公开导出”不能写成“内容已通过隐私检查”。

工作簿仅在本地以只读模式打开，原87366字节SHA前后一致。ZIP共26个成员，均为可解析XML，所有文本／属性有界扫描；14张表均可见，隐藏行列0，外部关系0，外部数据／嵌入不透明部件0。共检查17608个单元格位置、16752个非空单元格及8个公式，凭据模式候选0；没有保存、导出、重算或改动内容。此结果不代替配置业务正确性、公式结果或视觉排版验收，也不输出单元格、公式、作者或链接原文。

本轮新增11个不同的纯读取控制（schema6、配置角色5）均通过，不重跑已完成套件。检查器失败单独保留：工作簿R1因部分表缺少dimension声明，在迭代前遇TypeError退出1；R2改为有界实际位置计数后完成。配置角色复核R1误用column.type而非value_type，尽管进程退出0，其16043条疑点不计通过；R2严格按真实字段成功复核。初次测试路径拼写、配置包误按UTF8类型字段读取的失败同样保留，不作为产品缺陷或通过记录。

前轮6条旧工具／私有报告字节缺口本轮未关闭。标识符来源、完整像素隐私／OCR漏检、缓存内部内容，以及剩余root／schema／archive／replay环境与选择器关系继续开放；不能以本轮阴性结果宣布LOAD-11.2或整个132任务通过。原先44条分块schema误关联修正继续有效。没有云端代码上传或副本清理需求，本地测试代码及失败版本均归档保留。
