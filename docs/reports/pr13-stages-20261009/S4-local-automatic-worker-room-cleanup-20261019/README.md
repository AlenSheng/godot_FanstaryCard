# 本地自动后台房间清理补验

本轮补齐此前未验证的自动清理环节，未改产品源码。复用已实际构建的当前 Server DLL；328 个输入文本和 130 个产品 C# 源路径重新核对，12 个引用 DLL 字节一致。只离线编译独立验证入口一次，执行一次，37 项检查全部通过；没有重跑此前 40 个 Bots、10 个 Server 或 Web 矩阵。

3 个新场景：实际 RoomActor 100ms 定时 Tick 令纯机器人房间进入终局，持久快照与两个成员结算完成后，由实际 SettlementWorker.StartAsync 后台循环移除房间；活动真人标记的合成对照房间及路由在 3 次实际数据库扫描中保留；重新登记同一个已完成检查点后，新 Worker 实例又扫描 2 次并自动移除，首次结算时间和终局检查点均未改写。没有用手动 Advance、ProcessNextAsync 或 RemoveAsync 冒充自动清理。最终统一 Dispose 仅用于关闭剩余自有对照 actor。

独立 PostgreSQL 18.6 实际迁移到 V029。共新增 2 个本地夹具对局、4 个成员、0 个真实玩家账号；最终保留 1 Completed、1 Running、2 个 Settled 机器人。Running 行是刻意保持活动的合成对照，不是泄漏的真实玩家对局。11 张玩家、奖励、账本、装备与遗物相关表均为 0 行；这是声明初始夹具的无新增资产检查，不冒充新的非空机器人掉落实验。数据库快照先保存到 G 盘，两个 Worker Task 成功结束，actor／registry 及 PostgreSQL 正常关闭，数据原件保留，磁盘和内存均有至少 5% 余量。

本项单独预登记最多 2 个新数据库对局，未动历史容量 600 场记录。夹具 Npgsql 池为 8、PG 连接上限 32，只服务于功能验证，不产生默认池、容量或性能结论。没有游戏 HTTP、客户端、云端调用、上传或部署；所谓新实例重放仅为后台 Worker 对象重建，并非整个服务端进程重启。

本报告仅扩充机器人终止修复的自动后台链路证据，不替代全 PG 套件或整体验收。GDD v0.70 优先级、牧师合法 80/70 原始显示、132 任务／396 案例和 77 项未验收保持；register／gate／MAIN 未改，旧容量、Web CRC 与历史 AUDIT 缺口不改写。所有本地验证源码、构建入口、数据库快照和逐检查原件保存 G 盘，Git 仅同步精简报告。
