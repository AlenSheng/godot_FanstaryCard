# 九条待确认结算的本地副本恢复

本轮把已校验的测试数据库归档复制到隔离的本地 PostgreSQL，复用已验证来源的现有服务端运行包与当前 Native 客户端。副本中的 9 条待 ACK 全部完成确认；原云端数据库、原 100 人失败报告和原 9 条未 ACK 不改写。

21 个功能案例按测前矩阵核对：9 个既有账号恢复，3 个越权负例和 9 次重复 ACK。恢复分为正常、确认已提交后丢失响应、首次读取注入 500 三组，各 3 个账号。42 项 Native 检查通过；3 个越权请求均为 404，其他账号的 receipt 当时仍未确认。3 次丢失响应均先观察到真实 PG 提交，再断开连接；重试使用原幂等键，返回字节一致，每个 Native ACK 只新增一条持久化幂等记录。

覆盖全部 100 个测试账号的 9 张资产表共 28,316 行，在恢复、启动、登录、确认和重复确认五阶段的摘要完全相同。重复确认后首次持久化 ACK 时间不变，原 711 条 ACK 幂等记录加上本轮 9 个 Native 操作和 9 个重复操作，合计 729 条。副本仍为 100 个账号、180 个已结束世界、720 条结算，holds 和锁定装备均为 0。

102 条实际采样经过原审计与统计器核对，39 条逻辑 HTTP 事务对应 42 次传输尝试。3 个注入读取错误保留，9 个 ACK 仅记为 drain，不增加自然完成周期。测试期间无新账号、无新世界、无云端调用；应用正常退出，PG 干净停止。

缓存的 328 份输入与当前源码除换行外一致，130 个产品 C# 编译文档通过 DLL/PDB 校验。Portable PDB 校验按 [.NET 官方规则](https://github.com/dotnet/runtime/blob/main/docs/design/specs/PE-COFF.md#portable-pdb-checksum)在内存中清零 20 字节 ID 后计算，符号文件不改写。未进行 C# 构建；本地运行包与原云端 DLL 的字节哈希不同，来源与环境差异明确保留。

本轮是 LOCAL 副本恢复证据。9 个账号在一个 Native 进程内依次执行，不承担 100 人容量、同负载性能、真实玩家或云端连接超时裁决。原 600 世界保守预算及 132 任务/396 案例范围保留，register、gate、MAIN 状态不自动变更。
