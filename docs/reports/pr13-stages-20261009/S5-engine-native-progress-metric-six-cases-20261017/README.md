# 通信、等待与有效指标：实际引擎/正式协议/当前原生客户端

九个有效受控战斗场景：三个seed分别覆盖等待/满血治疗、部分治疗、控制重叠。本机一个有效等待场景与云端八场景组成完整矩阵；另四个接线诊断失败和一个首动作真实回归全部保留，总计14个场景，低于本次300场上限。真实当前BattleRoom产生状态和结算，正式RoomSnapshotProjection与Protobuf编码驱动当前GameStore/LoadClient，实际私有WebSocket往返；未手填客户端room/pending字典。

心跳与同一真实投影/同revision重复快照增加通信事件，玩法和有效进度时钟均不推进。实际PRI-01三级在当前有效满血80/80时请求治疗10、实际0，只耗一牌、零有效恢复，客户端未获知请求溢出时保持null及原因。余下两张合法牌通过实际指令消耗为空，实际ApplyStun1500ms投影被识别为stunned，真实ACK延迟500ms期间标为confirming；控制解除后足够蓄能产生真实自然抽牌，单牌健康蓄牌标为strategy_wait/intentional_hold，区别于卡死。

部分治疗三场均由实际TakeDamage2得到78/80，再由实际指令治疗10、应用2至80。报告recovery helper依据权威draft与capped结果算出溢出8，客户端本身未凭空填充不可见溢出。两个实际控制效果分别准入3秒、1.5秒且从同一逻辑时刻开始，30次100ms真实引擎推进观测union3秒，不能把4.5秒相加算成控制占比。

跨主机首次操作以实际request ID关联Windows发起与云端Stopwatch接收/执行记录。原生COMPUTERNAME环境为空，报告保持host未知及原因，不补造机器名；物理执行拓扑明确是本机↔严格SSH云端。不同进程/主机时钟没有校准映射，elapsed保持unavailable/null。客户端本机首次有效间隔、命令往返与权威端自身执行窗口分别记录，不混成HTTP P95；本轮没有生产HTTP请求样本，HTTP P95不造数。

**额外发现并修复：原负载驱动器_update_context在_observe_battle之前执行，首次动作已有权威battle ID却读空的跟踪器字段。** 原始空origin和真实battle ID同时保留。现在直接读取当前权威duel/PVE，优先活动duel而非冻结PVE。三个OFFLINE边界和一个真实首动作回归证明初始化前及实际origin正确；其他指标事件处理函数不变。B01.1原验收三案例记录保留，本轮补首动作缺口并做当前来源复核。

**诊断失败完整披露：** R1测试子类返回签名错误；R2未开启Gateway轮询；R3实验权威端未主动推首个room.started；R4仅推进4秒时约1.5秒受控期间暂停抽牌，仍无牌属于正常规则，不能报为游戏异常。当前按正式100ms步进推进6秒，未改抽牌或眩晕规则。有效场景和回归均无引擎错误。后来测试脚本加入两条首动作守卫，控制源版本差别与原SUT哈希明确，未重建或覆盖原生运行记录。

本轮是明确的合法受控合成入场：保留完整20张实例多重集合，仅PRI-01等级3，其他0，空装备/武器0；HP由当前引擎有效上限和真实受伤API得出。受控效果注入、模拟Domain逻辑时钟与实际网络/客户端单调钟分开。没有完整Program认证、PostgreSQL、自然远征、LIVE、容量、渲染或真人结论；不修改游戏公式、正式配置，也不把合法80/70当异常。
