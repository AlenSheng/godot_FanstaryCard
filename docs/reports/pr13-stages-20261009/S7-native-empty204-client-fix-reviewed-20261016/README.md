# 原生临时 HTTP 请求的空 204 响应修复

原生客户端收到真实 `204 No Content` 空响应时，原 `HTTPRequest` 临时请求路径返回状态 0，导致取消已在服务器提交后仍显示失败并重复请求。保存的原始响应在本机复现了相同问题；项目现有 `ReusableHttpClient` 能正确读取同一字节包。

本次让原生独立请求及共享连接忙时的回退请求使用独立的现有客户端实例，完成后关闭。共享连接的正常路径和 Web 分支保留。生产文件与验证通过的隔离候选逐字节一致。

验证覆盖原生独立请求、共享连接空闲和真实并发占用后的回退三个路径。真实公网 A04.1-T02 通过独立 HTTP、Protobuf 及 SQL 复核：原生产 READY 循环依次读取 Queued、Queued、Cancelled，恰好三次查询、零 READY；取消与清理均收到可确认的 204，账号无遗留锁定、hold 或未完成结算。

这是明确终态负例，原生载荷报告保留预期的 `ready_ticket_terminal` 失败检查，不计正常通关周期。既有失败原件、实际空 204 回包和全部候选证据均已在 G 盘归档并校验 SHA256 与压缩 CRC。

本报告不覆盖 Web 运行时、容量、延迟 SLO、RENDER 或真人体验。T03 的重复恢复请求反馈仍未解决。服务器未部署或修改配置，验收 register、gate 与 MAIN 未自动更新。
