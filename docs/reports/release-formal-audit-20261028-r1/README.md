最初主工作区扩展状态 3,287 条，其中 1,589 条的文件字节与 HEAD 完全相同，仅刷新 Git 索引状态；没有借此覆盖内容。生成的 editor 日志另存原件后恢复基线。真正的工具和文档改动单独审查。其他验收工作区中已合入的修复按内容核对；不同 UID 为各工作区导入时生成的身份，不互相覆盖。Google Play 发布工作区和其他功能／平台分支继续独立保留。

云端 `/opt/fantasycard-github` 原正式目录位于 `9c1feacfb76214a82ed9e427e4b770ee53c963d4`，跟踪文件干净，仅有两份私有 `.env.before-*` 备份未跟踪；这些备份不读取内容、不入库。云端源码比对共 22,960 条观察，17,928 条匹配当前 release，3,098 条匹配 release 历史，1,934 条为环境／历史副本差异，包含文档内复制代码与旧控制器；匹配允许明确的 BOM／换行归一化，不能把这种匹配称为所有原件逐字节相同。范围、差异清单及抽查见 `cloud-scope.json` 和 `cloud-variant-inventory.json`。

云端旧 `/opt/fantasycard-app/server` 与 `fc-release-qa-609e13e` 等副本早于当前协议、安全检查、房间同步和 Guardian 余盾规则，抽查其差异不构成未合入的现行修复。现行服务源码以正式 Git 检出及已部署镜像身份为准；本轮未发现需要晋升的遗漏现行业务源码。54 个非祖先分支只保留候选／历史身份，不整支合并；开放 PR 查询为空。未声称逐行验收全部历史候选代码，也未把仅存在的旧源码当成历史运行来源缺口已补齐。

## 验证与边界

台账恢复、回调公开回执及原有公开证据规则共 22 项测试通过；真实归档单成员恢复后 SHA 相符。恢复工具拒绝覆盖不同原件，校验清单、大小、路径和 SHA，并保留磁盘 3GB／5% 下限。所有新入库的公开文本重新检查；源码与证据分类及 Git 暂存范围另行核对。

整理过程保留了一次回调测试观察竞态的失败记录：客户端收完响应时处理器尚未写完回执，改为锁内等待完成后读取，业务断言未放宽。另有首版单成员解包性能停止、一次 Docker 只读命令缺权限、一次 SSH 超时的原始记录；这些都不是新容量实测，不计入容量通过场次。

本轮无新 Godot 负载、登录、容量或真人测试，无限流变更，无数据库／私有环境修改，无镜像构建或服务重启。云端同步仅快进正式 Git 目录；运行镜像仍是 `e647601a…`、源码标记仍是 `4a9215fe…`，不会把文档提交写成新镜像身份。本机／SJH 6GiB、云端 500MB 及磁盘 3GB／5% 保护不变。

当前结论继续为 **120 项 Accepted＋12 项容量按用户约定收口，待验收 0 项**。100 人批次原始未通过、测试客户端供给及监督器限制、SJH 4 核改为 24 逻辑 CPU 和 BelowNormal 的配额调整均保留；没有有效 100 人共同窗口，不能据此认定服务器无法承载 100 人。四项当前版本采用本机模拟口径，历史原件来源及真实外部 fork 未实测缺口单列保留。最终 UI 的中英两语言、三档分辨率 318 帧／714 项检查不重跑、不改写。
