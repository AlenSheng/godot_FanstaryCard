# A03 管理员解锁卡的副本流水

当前为待验修正，服务端尚未完成本机编译及Repository／HTTP验证；整体仍20/35。

`AdminRepository.UnlockAllCardsAsync`原来直接将未激活卡改为1张。账号已启用永久副本且该卡上一条流水余额为0时，解锁后聚合变为1，账本仍为0，`EconomyReconciliation`会报告差异。原管理员审计记录保留操作，但不能替代卡副本余额链。

修正只对已经启用永久副本、且本次确实新解锁的卡，沿原账号锁和同一事务追加`admin.unlock_all_cards`的+1流水，来源为原管理员requestId。已有卡及其储备、等级和版本不变；旧账号不被强制采用新政策，原授权、解锁范围、返回数量和重复请求冲突语义保留。永久储备约束保证待解锁卡没有正数储备，因此新余额为1。

使用代码中的原解锁SQL、实际卡流水INSERT及实际对账子查询，在既有隔离PG的精简TEMP表执行了合法前置状态反例。差异依次为：基线0、只执行旧解锁1、同事务加流水0、回滚到基线0。事务最终整体回滚，没有改变业务表。该证据只验证SQL层反例和预期账本效果，不是完整迁移、Repository或HTTP实测。
