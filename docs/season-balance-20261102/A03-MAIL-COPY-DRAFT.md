# A03 邮件永久卡副本缺口与待验修正

最新结论：C15已通过、整体21/35；邮件／管理员副本10项PG已通过。以下保留本文件阶段记录，当前证据与范围以[C15完整验收](C15-FINAL-ACCEPTANCE.md)为准。

这是一项源码审计和待验修正，尚未编译或完成真实PG验证；A03/A04/C15和整体状态不据此提升，仍20/35。

邮件Card附件原来始终把`player_cards.copy_count`置为1。对沿用旧激活语义的账号，这是既有行为；对已经按已发布新季政策启用永久副本的账号，则会漏掉重复卡和多张附件的真实副本。商店、季程和图鉴已有永久储备／副本账本，邮件尚未接入。

当前修正让邮件只在读取真实已发布政策后启用永久副本；旧账号继续原激活语义。同一原邮件内相同卡ID先按数量合并，再写真实储备与一条卡账本；不同邮件保留不同原mailId作为来源，不借当前大厅给无版本老邮件猜测赛季。奖励使用已经存在的玩家卡ID，不改永久等级、牌组和卡牌目录，不新造卡ID。现有商店／季程仍先校验其原配置定义，再进入同一储备写入原语。

单领与全领统一先锁账号再锁邮件，避免单领持有邮件、全领持有账号时形成交叉锁。原邮件已领取状态、持久幂等回执、储备和副本账本仍在同一事务内；业务拒绝及数量溢出保留HTTP400映射。未改协议消息、路由、邮件附件显示结构或历史回执。

新增`PostgresMailPermanentCopyTests`共8项声明的隔离PG用例，准备覆盖：旧账号语义、新政策在未打开商店／图鉴时生效、重复与新卡精确数量、单领／全领并发、回放及换键防重、删除邮件后的来源账本保留、部分写入故障回滚再试、非法ID／溢出、季末保留及账号归属。这里的8项是待运行的用例数，不是通过数，没有实战场次。

下一步资源满足后，运行G证据目录`run-mail-permanent-local-r1.py`做实际.NET构建和定向本机检查；所有新增PG用例必须在既有隔离PG实际运行，零跳过，并回归当前C13商店及C15领取的永久副本链。先前r108原程序集／原结果不动，不在云端调用SDK。只有新输入编译、自检和PG证据完整后才更新这项结论。

邮件未声明的赛季来源不按当前版本补造。未版本化的旧金币、碎片和装备邮件及其他资产写入还要继续综合审计；本修正不自动完成A03/A04，也不改变已结案容量口径或触发100人补测。
