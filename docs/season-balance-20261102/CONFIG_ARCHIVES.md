# 房间配置归档接入

本记录描述 C01 的服务端及客户端读取路径，完整季赛内容和最终发布仍未完成。C02已将集成本地包升至 `season-v1-config-1`，原 `gdd-0.70-numerical-1` 三件套保存在 `server/config/archive`；当前生产运行包未替换，新赛季未启用。

`GameConfig:ArchiveDirectory`（环境变量 `GameConfig__ArchiveDirectory`）指定归档根目录，建议部署时使用明确的绝对路径。每个版本一个子目录，包含原导出器生成的三件文件：

```text
<archive-root>/<config-version>/fantasycard.config.bytes
<archive-root>/<config-version>/fantasycard.config.version.txt
<archive-root>/<config-version>/fantasycard.config.sha256
```

版本目录名、版本文件和包内版本必须一致。侧文件保存原编译器定义的内容哈希：对未写入 `content_hash` 字段的原 Protobuf 消息计算 SHA-256；该值与整个发布文件的 SHA-256 不同，两者不可混用。目录加载验证包内内容哈希以及预期版本/哈希。已加载同版本不会被磁盘上的另一份内容替换，缺失或损坏版本不能回退当前配置。

目录和文件须对服务端容器的运行用户可读，并以只读方式挂载。此目录只保留发布配置三件套；数据库备份及私有连接配置沿用原有独立位置。

开局协调器、启动恢复和已结算房间补读选择房间/匹配记录的确切版本。恢复失败按房间隔离，原持久快照保留；终态补读无法取得原包时拒绝命令，不注册临时 actor，也不写新结算。当前大厅版本仍由嵌入包决定，读取旧版本不切换大厅配置。

领域房间的卡牌基础值与成长、背包定义、药水、奖励刷新费用、三选一生成/刷新、自然格奖励、怪物卡查询和装备换装都沿用同一目录。背包事务副本与遗物转移保留原目录，快照恢复把该目录传给背包和待选奖励。已存装备战斗投影继续按原快照保留，后续换装才按该房间目录重新计算。

新 `CombatCardCatalog.Create(已验证目录)` 会校验房间版本一致性；服务端运行路径统一使用它。`CreatePrototype()` 保留现有独立领域夹具的任意标签约定，不作为服务端加载未知版本的途径。

正式替换运行包之前，F03 仍须把旧运行包的三件原件与哈希存入固定版本目录，持久挂载该目录并配置上述路径。保留至所有旧房、晚结算和终态补读完成，再按明确的保留策略清理；当前没有自动清理归档包的任务。本轮不会先替换生产包或重启未完成的赛季实现。

本批控制配置有意使用不同的卡牌伤害/成长、装备属性、背包容量、药水和奖励价格，以证明消费点隔离。这些值不写回正式工作簿，不作为 C02/C05 或 D03 平衡验收。客户端读取批次见下文，完整渲染UI、机器人生成版本投影及新季内容表仍需后续验证。

## 客户端读取

已接入带鉴权和既有读限流的 `GET /api/v1/config/{configVersion}`。HTTP回应使用追加的 `PublishedConfigurationResponse` Protobuf 消息，包含版本、内容哈希和原发布包bytes；没有新增JSON配置读取途径。两端沿用同一发布包，客户端只把Both/Client列加入显示目录，Server列不进入UI索引。

Bootstrap发现未结束房间或旧季结算时，先校验原包及预期版本，再采用该房间路由。缓存属于当前GameStore和服务器来源，身份重置清空，迟到的会话/来源响应不能写入。大厅仍使用内置目录；房间预览、卡牌成长文字、怪物卡及装备比较显式选择原目录，缺失目录不回退当前数值。失败提示已覆盖现有11种语言，说明稍后重试，避免误提示更新客户端。

Godot原生验证使用真实C#编码的两个包和HTTP外层：209项布尔检查通过，独立HTTP传输27项、实际autoload环境5脚本加载及11语言包审计通过。这里只验证数据、文本与加载；没有产出多分辨率渲染帧，完整UI效果仍待E02。初始组合运行器误把SceneTree脚本当run_test套件造成两次90秒超时，以及check-only缺autoload的失败，原件均保留在 `evidence/C01-config-client`。
