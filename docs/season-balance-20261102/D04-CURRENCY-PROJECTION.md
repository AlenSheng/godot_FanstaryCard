# D04 账户币分账与只读汇总

2026-11-06。本子链路通过，整体仍30/35，D04保持进行中。已实现持久账户币的来源分类、刷新预留生命周期与私有管理汇总，不把它当作11类事件、实物及按实际局时统计的完整遥测验收。

## 当前行为

从已有economy_ledger、market_transactions和reward_refresh_operations投影，不建第二份资金账，不因查询重试追加投放计数。使用固定币种/流类别/渠道，将永久魂与钻石、原季币及未声明旧域分开；未识别币种、理由或历史ClassSoul保留Unclassified，不补成当前季或某个职业魂。

市场买方总扣款和卖方净得只作为账户移动，转移量按每笔交易的净额计一次，只有明确税费计系统回收。交易通过原买卖账本身份和金额核对资金季域，不拿装备来源季猜付款钱包。合法最低税费可使卖方净得零且没有卖方账本行，仍识别为一笔转移和一次税费；缺失或重复的资金腿会明确降低覆盖度。

刷新reserve只是账户到预留的移动；refund是释放预留，均不凭正负号当作新增/销毁。状态转为Applied时，已扣账户的原预留被消费并识别为NPC回收。一次查询窗口可只含消费而不含更早的预留，公式同时保留预留变化与账户变化，避免再次记一笔扣款。依据是已有account_gold和持久Applied状态；原收据没有accountGoldSpent字段，未发明或回填这个不存在的来源字段。

V053只追加可空applied_at及状态一致性约束。生产者仅在Reserved→Applied首次转换记录时间；重放保留原时间，旧Applied缺时间的记录重放后仍为NULL。不能用可被重放改动的updated_at冒充历史首次应用时间。该观测字段不改变支付金额、资产或业务状态转换，受影响的F02资金/幂等范围已定向复验。

## 汇总接口与精度

新增`GET /api/admin/telemetry/economy`，复用原管理HTTPS、X-Admin-Key、速率限制及private/no-store边界；不增加公开游戏JSON入口。from/to为左闭右开UTC窗口，默认一天、最大七天。RepeatableRead加只读事务保证三个来源观察同一快照；五秒总取消/单句超时及每源10000组上限保证有界，截断和未知覆盖显式返回。

输出包含币种/付款季域的系统新增、回收、转移、预留/退款/已用预留、原账户增量、可解释增量及差值，以及具名渠道明细。数额经PostgreSQL整数聚合和BigInteger处理，以精确字符串返回，避免超过2^53时JavaScript丢精度，也正确处理long.MinValue绝对值。

coverage字段描述投影是否有完整解释，不是游戏经济健康或异常判决。历史缺时间、未知理由和ClassSoul歧义都保留；不能看到覆盖缺口就自动判定资金异常。实地尚未带出的潜在掉落、实物和游玩时长不混入这个账户币报表，perAttemptPlaytimeRatesAvailable明确为false。

新增的查询耗时meter只有固定四值outcome标签，不按查询结果重复上报投放数量，也不把player_id、match_id、item_id、原始理由或季ID放进指标标签。管理报表本身允许返回资金季域元数据，仍受管理鉴权和禁止缓存保护。

## 实际验证与保留记录

15项当前单元检查通过：最低整数税、转移不重复、预留/释放/消费跨窗口、永久魂不按来源季拆钱包、未知ClassSoul不猜职业、超大整数、窗口边界及有限指标标签。首轮两个分析器编译错误均未执行用例，修正后通过，原记录保留。

真实隔离PG与管理HTTP按首批4通过＋一项定向复验联合5项，不称一批全新全绿。两次真实市场成交覆盖Gold价格1/税1/净得0，以及Diamond2000/税200；查询前后全部账户币、账本、市场和刷新行指纹完全相同，查询重放不投币。夹具初始资金在测量窗口之前，未把测试注资当作生产渠道。

真实Reserve、Applied、重复Applied、Refund均执行。首次时间固定，重复Applied后updated_at可以按既有行为变化，但原时间不变，重放窗口没有虚假新消费；七金被消费、五金预留后退回，最终原季余额93。旧缺时间Applied夹具不被重放补时间，歧义ClassSoul保持未分类。首批唯一失败为夹具将驱动返回的UTC DateTime强转DateTimeOffset；按驱动类型和PG微秒精度修正夹具后，仅复验这一项，没有削弱金额、状态或重放断言。

一个完整Program进程实际验证管理JSON入口：缺密钥401、缺安全转发信息403、合法请求200及禁止缓存，过宽/最小日期边界400。此为自有回环HTTP与既有转发语义，不宣称实际公网TLS握手。新迁移V053在实际服务启动日志及PG用例中通过。

定向复验首次SSH传输途中重置。只读确认远端仅等待未完成输入，没有测试容器、私有配置或输入挂载；以精确启动参数SHA和python进程身份，只SIGINT本批等待worker，使其finally收尾，未碰其他项目。原传输、资源日志和终态取回并验SHA。随后复用项目SFTP方案：32MiB专属tmpfs中先传完整文件并校验，再启动读取本地文件的脱离SSH worker，只执行原来失败的一项。测试和上传tmpfs均已卸载，六个实际测试schema、两个容器、私有env均已清理，共享自有PG保留。

所有原失败、可选Kerberos库诊断、编译/输入/输出SHA和本机原始程序集继续保留。没有更改正式工作簿、卡牌、资源、美术、游戏UI或云端生产服务；没有新增B05/D03/D02战斗或100人测试。证据见[结果](evidence/D04-currency-r1/result.json)及[独立审计](evidence/D04-currency-r1/d04-currency-independent-audit-r1.derived.json)。
