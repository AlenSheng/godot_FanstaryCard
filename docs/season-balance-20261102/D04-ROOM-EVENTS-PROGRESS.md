# D04 房间战斗与掉落原始事件

2026-11-06。本子链路通过，整体仍30/35，D04继续进行中。新增battle_finished、loot_generated、loot_chosen、loot_extracted、loot_lost的有界原始观测和私有导出；不是完整战斗明细、统一构筑/成长维度、实际资产提交或完整经济验收。

## 生成、合并与恢复

新建且有权威UTC开局时间的房间启用可空Observations检查点字段。单房累计序列从1开始，事件ID为room_id加原序号，不消耗任何游戏随机流。累计列表进入原房间JSON，关键检查点标记追加LastSequence；队列把多个纯保存合并为最新快照时，最新快照仍有全部先前事件。不另建独立资产账或内存日志代替持久权威。新事件与对应游戏检查点同一个数据库写入，失败不会把观测与该检查点拆开提交。

每房最多4096事件、每事件最多128物品；超过后保留原序列与DroppedEvents/OmittedItems，不能无限占内存或静默宣称完整。静态边界夹具预置4096条元数据后只触发一次刷新，验证新增三条缺口，不是4096场测试。旧缺Observations的房间保持未观测，包括已经有StartedAtUtc的旧房；不因恢复或新程序启动补造旧事件。新记录版本、序号、玩家/职业/机器人身份、逻辑时刻、UTC映射和物品边界不一致会拒绝恢复或在管理投影报告缺口，不自动修复原件。

## 事件语义

- battle_finished记录真实PVE结束/放弃/断线、PVP死亡/存活退出和机器人结束边界。PVP死亡时同时记录无法再恢复的原冻结PVE中断，区别两个battle_id；成功清格和失败结果分开。机器人模拟结束明确标识BotPvp/SimulationEnded或Terminated，不当作真人真实Resolver胜利。
- loot_generated区分基础格实际生成、初始/刷新潜在三选一、机器人胜利奖励和已由独立事务铸造的红装交付。三选一每个候选一条PotentialChoice，不把三个备选都记为系统实际投放。基础掉落/机器人溢出明确OverflowRecycled，携带仍为待结算。红装为AlreadyMintedDelivery，不再次记铸造。
- loot_chosen只在实际领取成功后写，保存原option_id、实际应用数量、回血比例及领取前血量；满血实际回复0也入样。刷新请求的原幂等收据先返回，重放不再生成候选；失败请求不伪装成功。遗物堆取物另标RelicTransfer，是取回/转移而非新生成。独立红装替换原已铸物品不二次投放。
- loot_lost记录死亡或主动替换转入遗物堆的实际物品，明确RelicCustodyPendingSettlement；安全物品的现有游戏规则继续决定保留。遗物可被取回/转移，不能把此事件当作永久销毁。机器人终止另标BotTermination。
- loot_extracted记录原逻辑倒计时完成的物品与RoomExitPendingSettlement，不拿大tick末尾代替实际退出时刻，也不把它当作资金/实物已经提交。永久提交和托管状态仍以原Settlement账/holds为准，不能再按本事件加一次账户信用。

事件保存原职业/机器人标识、位置/格类、battle_id、房间逻辑时刻和开局UTC映射；原季及规则/配置/属性版本来自同一个原匹配上下文。血量同时保留EffectiveMaximumHp，不拿基础职业70/80判定合法超血异常。原始物品保留实际数量、品质、来源生成/安全/投影标识；当前不从这些字段假定市场价格或职业构筑类别。Build/Growth统一维度及完整逐动作战斗统计仍未完成。

## 有界只读导出

新增GET /api/admin/telemetry/room-events，继承管理HTTPS、密钥、限流及private/no-store。RepeatableRead只读、五秒总截止/语句超时、最大七日UTC左闭右开窗口。每次最多1000源房间/1000返回事件，单房观测JSON超过4MiB单列无效，截断、旧房未观测、坏记录、缺UTC、丢事件和物品省略均明确返回，FullyObserved仅指当前原始来源窗口，不表示D04所有维度/经济健康。

时钟为原开局UTC加权威逻辑Elapsed，包含断线/恢复推进，不是测量真人活跃操作时间。缺时刻不能分配假时间；掉事件发生窗口不明确时保持保守缺口。公开第一方协议仍由原RoomSnapshotProjection/具名Protobuf消息逐字段投影，没有新增公开journal字段。ID只用于受鉴权结构化分析，现有meter仍只有固定查询结果标签。无客户端、协议生成文件或数据库迁移变更。
