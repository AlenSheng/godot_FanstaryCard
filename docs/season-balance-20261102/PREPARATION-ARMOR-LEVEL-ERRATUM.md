# 准备页防具等级预期纠正

本批r104的真实PostgreSQL用例首次运行失败：准备快照中防具等级为5，而新夹具错误预期为1。此失败不是服务端把防具错误提升到了5，也不能据此改变既有规则。

冻结设计第2.5节（source/Season_Balance_Design.md第66段）规定D0至D5对卡牌、专武使用+0至+5的有效等级帽。防具受入场品质帽、原季/属性版本和橙红合计一件限制，其真实强化等级继续保留。PreparationRepository的装备快照直接保存物品等级；卡牌与专武另行投影。RoomReadyCoordinator按原防具等级计算原版本属性。

核对上述契约后，将夹具改为预期防具5，并删除尚未提交的客户端草稿中将防具投影到1的实现。客户端现在复制原防具数据，卡牌与专武仍按D1显示1，永久卡级、专武与防具存档均保持5。

r104原结果0通过/1失败完整保留，测试容器及私有env在原件下载与SHA验证后清理。r105沿原门槛真实重验1通过、0失败、0跳过，实际覆盖自有和借用两种准备状态及准备前后Bootstrap编码，不能叙述为首次即通过。

这与合法80/70生命值的口径相同：先核对原文、数据含义和实际消费路径，再分类异常；不能把合法数据与错误测试预期混为服务端缺陷。正式数值表、服务端规则和历史数据未因此改动。
