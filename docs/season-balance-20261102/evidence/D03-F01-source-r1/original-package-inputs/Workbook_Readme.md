# 赛季数值工作簿说明 · v2

`Season_Balance_Model.xlsx` 是候选方案的可调测算表，包含 13 张工作表：总览、参数、成长与装备、难度与怪物、怪物展开、掉落概率、路线经济、赛季进度、配置字段、红装周投放、双币市场、商店与活动、全服资源账。

## 使用范围

- 淡黄色单元格为可调输入；灰色单元格为固定结构或规则参考。主要结果来自 Excel 公式，调整黄色输入后会联动重算。
- P0 是假定已经拥有三张样本卡的裸装算术锚，三卡基础值为 8、3、12；不是新号初始 20 张卡组的表现。吞吐代理不是 DPS、TTK 或胜率。
- R1 收益只针对给定出生点与 Boss 坐标下的 5 外层、1 中层、1 精英、1 Boss 条件路线；18 分钟和 70% 撤离率都是待实测假设。
- 1 橙 4 紫强化 +3 为 60 碎片；加已学模板重铸为 66 碎片。D2 的每次期望净额分别为 10 和 8.2 碎片。这里只核算碎片，装备本体、金币、药剂和其他消耗须另验，不能据此证明整体养成可持续。
- D0/D1 不能带入橙装，对这两档展示 1 橙 4 紫重建只属于跨档压力参照。
- 季程并列连续时间均摊和每日整局口径。30 分钟只能容纳一局的情形，不保证 42 天达到 30 级。周契约使用完成率与周均摊，未模拟具体完成日。
- 怪物 HP、盾与首个普通元素意图采用逐步取整。Boss 第二阶段属于同一个实体，表中列出的第二阶段最大生命不是额外一条血量；循环盾倍率、蓄力及强化顺序需依照主报告接入真实战斗实现。
- 新规则、难度倍率、装备价格、掉落表、印记与赛季机制均为提案；工作簿没有写入生产配置。

## v2 新增口径

常规五色掉落表仍最高橙色；D2 起允许带红并另走红装独立判定。保留每逻辑服每自然周最多生成 1 件红的共享硬配额，不保证每周必出。红装页默认采用 42 天对齐的 6 个完整自然周，真实首尾周应按服务器时区和周键另行枚举；相邻赛季共享周配额，死亡、交易或材料消耗不返还额度。红 +5 的 390 碎片是候选费用，仍需本体加两件真实红材料，不代表单人获取保证。

重铸消耗真实同品质本体，输出 +0，继承绑定与赛季限制。合格原始装备只能提取一次配方，交易保留标记；重铸产物、红装、借用、Bot 投影和活动纯材料不能提供新配方。借用、Bot 投影及活动纯材料不能作为可穿戴重铸本体。正常绑定碎片可用于加工合法可交易装备，不会因此把全部强化装备自动绑定。

普通商店使用原文档价格和限购；购买频率是候选假设。日均 0.5 包表示群体平均频率，不代表单个账号能买半包。6 金/碎片是购买成本折算，不能卖回金币。修改碎片包购买频率会同时改变资源与金币回收。

活动采用 42 天两期、每期 12 章的候选例子。80% 完成比例表示参与者中拿满 12 章的账号比例，其余参与者本例不兑换，不是人人平均进度 80%。四个兑换分支共享预算，不能叠满；兑换奖励乘参与、完成与兑换三项条件率。直接金币、钻石及装备默认均为 0，压力输入只乘参与与完成，不再乘兑换率。红直接奖励保持 0，任何红投放都必须占用同一周配额。

市场按金币与钻石分账，成交额属于转移，只有手续费属于系统回收，默认不开 NPC 钻兑金。市场深度中的 25% 表示同时符合交易资格且实际挂牌的综合比例。自然掉落、正常打造和活动直发才新增装备本体；重铸 1 入 1 出不新增本体；被别人最终带出的死亡遗物属于转移。挂牌是托管，不是销毁，也不是无限仓库。

新增全服账使用每日完整局数，默认 `floor(60/18)=3`。基础路线页只算基础格奖励；独立三选一、商店与活动列在新页，不可重复相加。D2 三选一 2 倍分支逐个原始整数先乘所有倍率再取整，均值 86.5，不是 40 × 2；其额外日均为 19.92375 碎。计入商店每天 20 碎、活动均摊 0.822857 碎，再扣常规 66 碎死亡重建，得 65.346607 碎/人日，尚未扣可选 +4/+5。

全服每 1,000 次尝试默认额外将 25 件橙、100 件紫从 +3 升至 +5，消费 18,000 碎、50 橙材料、200 紫材料；剩余约 3,782.202381 碎，橙本体净增 20.5、紫本体净增 265.75。旧装最终回收率从 50% 降至 25%，同样升级规模变为净缺 54.5 橙、34.25 紫。碎片账正结余不等于本体充足，更不保证每个玩家可持续。

默认全部已列商店、药剂、刷新和税费后，金币净变化为 32.75 金/活跃人日；钻石新增默认 0，市场税每 1,000 次尝试消耗 250 钻，依赖既有余额，不能称为健康新增供给。实际价格、挂牌率、资金集中和玩家分层均须实测。

新页的输入检查覆盖三选一概率和、0 至 1 概率范围、递减的三次刷新频率、币种与价格上限、活动互斥预算；异常会显示“检查输入”等提示。这是测算状态提示，不替代服务端校验。

## 构建脚本

`build_workbook.mjs` 保留构建、重算、输入边界核验、预览与导出流程，没有自建模块依赖。需要可解析 `@oai/artifact-tool` 的 Node 运行环境；本次使用主运行时 Node。中文预览使用系统可见的 `Noto Sans CJK SC`，未附带字体或依赖包。

四个位置参数依次是基础模型、输出目录、独立算术参考、市场扩展模型：

```bash
node build_workbook.mjs analysis/season_model.json rebuilt analysis/arithmetic_results.json analysis/market_model_v2.json
```

同目录交付输入也可运行：

```bash
node build_workbook.mjs season_model_inputs.json rebuilt arithmetic_results.json market_model_v2.json
```

无参数时，以脚本目录下的 `season_model_inputs.json`、`arithmetic_results.json`、`market_model_v2.json` 为输入，输出到脚本目录下的 `rebuilt/`。基础模型与市场模型提供本轮参数；`arithmetic_results.json` 和市场模型中的 `results` 仅用于独立核验，不会替代计算公式。传入另一套候选基线时，脚本中固定预期校验也需同步调整；普通敏感性试算直接修改工作簿黄色单元格即可。
