# 后台管理

管理页面：`https://43.172.70.182:20000/admin`。现有 80/443 端口不会转发 `/admin` 和 `/api/admin/*`；20000 端口仅转发这些后台路径，其余路径返回 404。页面需要 `FANTASYCARD_ADMIN_KEY`，必须是至少 32 字符的随机密钥，存入服务器 `server/.env`，不要提交到 Git。后台未配置密钥时返回 503；HTTP 请求被拒绝。云安全组是否对外放行 TCP 20000 由服务器管理员控制。Docker 发布端口可能绕过主机上的 UFW 规则，建议以云安全组作为开关。

当前 `ip2.crt` 没有 IP SAN 扩展，浏览器会提示证书不受信任。正式使用前应换成包含 `43.172.70.182` 的 IP SAN、且客户端信任的证书，或改用有效域名证书访问 20000 端口。

游戏客户端默认连接 `https://www.relicbound.cn`，Godot 会校验公有 CA。`Caddyfile` 里的域名站点必须走自动 HTTPS（Let's Encrypt），**不要**再加 `:443` 兜底站点并挂上 IP 自签证书，否则域名握手也会拿到 `CN=43.172.70.182`，客户端会显示服务器不可用。IP 自签证书只用于 `43.172.70.182` 和 `:20000`。

后台可按 UID、精确昵称或平台账号查找玩家，查看基础资源与背包装备，发送留言和带附件的邮件，收回资源或背包装备，封号及解封。发放的附件由玩家在邮件中领取；收回在一个数据库事务中即时完成，并发送通知邮件。背包外的装备暂不可收回。

所有写操作要求 `Idempotency-Key`；审计记录在 `admin_audit`。封号会删除登录令牌并断开当前 WebSocket。解封后玩家需要重新登录。可发放的类型为金币、钻石、四种魂、装备碎片、药剂、背包和装备。装备格式是 `品质|元素|部位`（例：`White|Fire|Head`）；收回装备填写背包中的实例 UUID。

上线时先备份 PostgreSQL，再构建并重启 `server` 容器。`V022__admin_operations.sql` 自动建立封禁与审计表。`Caddyfile` 无需改动。更新后检查 `/health/ready` 和后台页面；先在测试账号验证邮件领取、收回与封禁。
