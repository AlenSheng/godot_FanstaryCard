Cloud-only two-player optional monster pool boundary supplement. Both real room
players use the validated standard twenty-card deck, original HP, naturally
generated map, real PVE and actual typed router/RoomActor commands. Each player's
own published spawn coordinate is shared by the externally declared rendezvous
plan. The common public cell minimizes the maximum grid distance to either spawn,
then total distance, with deterministic public coordinate ties. No other hidden player position, library order or monster layout is
read by the movement policy.

Both players wait at their first genuine reward choice for the cross-owner
candidate probe, then legally accept their own candidates and heal if offered.
They move through the public map toward the common cell, clear natural PVE and
claim real rewards. A same-cell move must create the duel through production
pairing. An actual JSON room checkpoint during the duel is restored, and both
players request mutual leave through the typed router. Every later natural duel
is handled in the same way, and an extraction interrupted by a duel can be
requested again only when the original channel is absent. Death, no path and budget
censoring are retained; absent foreign/PVP/terminal branches are not accepted.

There is no direct StartDuel control, artificial HP, injected Offer, relocated
card, altered map or synthetic client payload. The capacity arms share fixed
seeds, starting identities and policy. This is a boundary coverage supplement,
not an independent balance sample, WAN load test or rendering acceptance.

`--guardian-peer-rendezvous` adds a separately declared encounter scenario. The
primary player keeps the selected hero and published spawn as the meeting point;
the second player uses the validated standard Guardian deck and walks there by
real legal movements/PVE. Both players keep their own twenty-card starting deck
and original hero stats in all capacity arms. This permits testing a Mage who
holds position against an arriving opponent. Earlier same-hero travelling routes
and their deaths remain intact; the scenario is not pooled into balance samples.

`--capture-render-vectors` collects actual typed public snapshots for one known
foreign rejection, one original choice and exact replay, and one PVP/return per
route. Snapshot collector requests and render replay probes are explicit extra
instrumentation. No domain snapshot is converted into a synthetic server frame.
